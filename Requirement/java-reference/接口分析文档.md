# 雅迪 PLM-SAP/MDM 集成接口分析文档

## 一、项目概述

本工程是部署在 **Oracle Agile PLM** 服务器上的一组 **Process Extension (PX)** 插件，用于在工程变更单（ECO）审批发布时，自动将物料主数据和 BOM 结构同步到下游系统（SAP ERP 和 MDM 主数据平台）。

- **所属企业**：雅迪电动车（Yadea）
- **集成供应商**：捷信（jiexin）
- **运行环境**：JDK 1.8 + WebLogic + Agile PLM 9.3.x
- **触发方式**：ECO 变更单工作流节点触发 `ICustomAction`

---

## 二、功能总览

本工程共包含 **4 个对外接口调用**，由 **6 个 PX 类** 编排：

| 序号 | 接口名称 | 协议 | 目标系统 | 调用类 |
|------|---------|------|---------|--------|
| 1 | 物料主数据创建/修改 | SAP RFC (JCo) | SAP ERP | `PlmRequestSap` |
| 2 | BOM 创建 | SAP RFC (JCo) | SAP ERP | `PlmBomToSap` |
| 3 | BOM 修改 | SAP RFC (JCo) | SAP ERP | `PlmBomToSapUpdate` |
| 4 | 物料主数据同步 | HTTP POST (REST) | MDM 平台 | `MdmUtil` |

PX 编排类：

| PX 类 | 职责 |
|--------|------|
| `ItemToSapTestPx` | 综合入口：依次调用接口1、2、3 |
| `ItemToSapCreate` | 单独调用接口1（仅创建） |
| `ItemToSapUpdate` | 单独调用接口1（仅修改） |
| `BomCreateToSapTestPx` | 单独调用接口2 |
| `BomUpdateToSapTestPx` | 单独调用接口3 |
| `ItemToMdmTestPx` | 单独调用接口4 |

## 四、接口详细分析

---

### 接口 1：物料主数据创建/修改（PLM → SAP）

#### 基本信息

| 项目 | 说明 |
|------|------|
| RFC 函数模块 | `ZFM_TR_MATERIAL` |
| 输入表参数 | `IT_DATA`（配置项 `SAP.REQ`） |
| 附加输入表 | `IT_LIST`（物料描述辅助表） |
| 输出表参数 | `ET_DATA` |
| 调用工具类 | `PlmRequestSap.plmToSapItem()` |
| 触发 PX | `ItemToSapTestPx` / `ItemToSapCreate` / `ItemToSapUpdate` |

#### 触发条件

- 变更单受影响物件的 Agile Class 父类为 `PartsClass`
- 物料属性 `ATT_PAGE_TWO_LIST01`（是否MDM）**不等于** `"Y"`（即非雅迪自管物料才走SAP）
- 通过旧版本号（`ATT_AFFECTED_ITEMS_OLD_REV`）判断是新增还是修改：
  - 旧版本为空 → **创建**（`ZCZLX = "01"`）
  - 旧版本非空 → **修改**（`ZCZLX = "02"`）

#### 输入字段（IT_DATA 表）

| SAP 字段 | 含义 | 数据来源（Agile PLM） |
|----------|------|----------------------|
| `ZCZLX` | 操作类型（01=创建, 02=修改） | 根据旧版本号判断 |
| `BISMT` | 旧物料号 / 物料号 | `item.getName()` 或属性 2011 |
| `MATNR` | SAP 物料号 | `item.getName()`（修改时） |
| `ZCWB` | 物料描述 | 属性 ID 1002（Description） |
| `MTART` | 物料类型 | 属性 ID 1274（单选列表 API 值） |
| `PRDHA` | 产品层次 | 属性 ID 1275（单选列表 API 值） |
| `MATKL` | 物料组 | Agile Class 名称前5位 |
| `MEINS` | 基本计量单位 | 属性 ID 1271 |
| `WERKS` | 工厂 | 属性 ID 2090（多选，按分号拆分逐行发送） |
| `ZZT` | 物料状态 | 生命周期阶段：停用/EOL→"ZTT"，其他→"ZSC" |
| `STAGE` | 生命周期阶段 | EV/DV/PV→"A"，MP→"B" |
| `ZKPDW` | 固定值 | "个" |
| `ZZZPL` | 固定值 | "物料组" |
| `BISMT_T` | 旧物料号（传输用） | 属性 ID 2011（非空时） |
| `BISMT_X` | 旧物料号更新标记 | "X"（当有旧物料号时） |

#### 附加输入表（IT_LIST）

| SAP 字段 | 含义 | 值 |
|----------|------|-----|
| `BISMT` | 物料号 | 同主表 |
| `ZCWB` | 物料描述 | 同主表 |
| `SPRAS` | 语言代码 | 固定 "ZH" |

#### 输出字段（ET_DATA 表）

| SAP 字段 | 含义 |
|----------|------|
| `MATNR` | 物料号 |
| `E_STATUS` | 状态（S=成功, E=失败） |
| `E_MSGTXT` | 返回消息 |

#### 后处理逻辑

物料创建成功后，将本次发送的工厂（WERKS）回写到 Agile PLM 物料的 `ATT_PAGE_TWO_MULTILIST02`（已同步工厂列表），实现增量同步追踪。

### 接口 2：BOM 创建（PLM → SAP）

#### 基本信息

| 项目 | 说明 |
|------|------|
| RFC 函数模块 | `ZFM_CREATE_BOM_NEW` |
| 输入表参数 | `IT_DATA`（配置项 `SAP.BOM.CREATE-REQ`） |
| 输出表参数 | `ET_ERROR` |
| 调用工具类 | `PlmBomToSap.plmToSapBom()` |
| 触发 PX | `BomCreateToSapTestPx` |

#### 触发条件

- 受影响物件父类为 `PartsClass`
- 满足以下**任一**条件：
  - 旧版本号为空（全新物料），直接取当前 BOM
  - 旧版本号非空，但上一版本 BOM 为空（`AgileUtils.getOldBom()` 返回空列表），说明是首次建立 BOM

#### 输入字段（IT_DATA 表）

| SAP 字段 | 含义 | 数据来源（Agile PLM） |
|----------|------|----------------------|
| `PARENTNUM` | 父物料号 | `item.getName()` |
| `SUBNUM` | 子物料号 | BOM 行 `iItem.getName()` |
| `SUBQUANTITY` | 用量 | `ATT_BOM_QTY` |
| `SUBUNIT` | 单位 | `ATT_BOM_ITEM_LIST11` |
| `LINENUM` | 行号 | `ATT_BOM_FIND_NUM` |
| `FACTORYNUM` | 工厂编号 | `ATT_PAGE_TWO_LIST02` |
| `ZKGL` | 客供料标记 | 子件物料类型="客供物料类型"→"X"，否则空 |

#### 过滤条件

- BOM 行的"替代属性"（属性 ID `2000019515`）非空且不等于 `"1"` 时跳过该行

#### 输出字段（ET_ERROR 表）

| SAP 字段 | 含义 |
|----------|------|
| `PARENTNUM` | 父物料号 |
| `SUBNUM` | 子物料号 |
| `Z_EXEFLAG` | 执行标志（S=成功, E=失败） |
| `Z_EXEMSG` | 执行消息 |

### 接口 3：BOM 修改（PLM → SAP）

#### 基本信息

| 项目 | 说明 |
|------|------|
| RFC 函数模块 | `ZFM_UPDATE_BOM_NEW` |
| 输入表参数 | `IT_DATA`（配置项 `SAP.BOM.REQ`） |
| 输出表参数 | `ET_ERROR` |
| 调用工具类 | `PlmBomToSapUpdate.plmToSapBom()` |
| 触发 PX | `BomUpdateToSapTestPx` |

#### 触发条件

- 受影响物件父类为 `PartsClass`
- 旧版本号**非空**（已有历史版本）
- 上一版本存在 BOM（`AgileUtils.getOldBom()` 返回非空）

#### 操作类型判断（基于 Redline 标记）

| Redline 标记 | 操作类型 `OPERATIONTYPE` | 含义 |
|-------------|------------------------|------|
| `FLAG_IS_REDLINE_ADDED` | `01` | 新增 BOM 行 |
| `FLAG_IS_REDLINE_MODIFIED` | `02` | 修改 BOM 行 |
| `FLAG_IS_REDLINE_REMOVED` | `03` | 删除 BOM 行 |

**修改行的特殊逻辑**（替代属性 `2000019515` 变化时）：
- 旧值为空或"1"，新值不为"1" → 按删除处理（`03`）
- 旧值为空或"1"，新值为"1" → 按修改处理（`02`）
- 旧值非"1"非空，新值为"1" → 按新增处理（`01`）
- 其他情况 → 跳过

#### 输入字段（IT_DATA 表）

| SAP 字段 | 含义 | 数据来源 |
|----------|------|---------|
| `PARENTNUM` | 父物料号 | `item.getName()` |
| `SUBNUM` | 子物料号 | BOM 行物料号 |
| `SUBQUANTITY` | 用量 | `ATT_BOM_QTY` |
| `SUBUNIT` | 单位 | `ATT_BOM_ITEM_LIST11` |
| `LINENUM` | 行号 | `ATT_BOM_FIND_NUM` |
| `FACTORYNUM` | 工厂编号 | `ATT_PAGE_TWO_LIST02` |
| `ZKGL` | 客供料标记 | 同接口2逻辑 |
| `OPERATIONTYPE` | 操作类型（01/02/03） | Redline 标记判断 |
| `SWITCHINGMODE` | 切换模式 | 固定 `"01"` |
| `MCNNUM` | 变更单号 | `ATT_COVER_PAGE_NUMBER` |
| `EFFECTIVEDATE` | 生效日期 | 当前日期（`yyyyMMdd`） |
| `AETXT` | 变更原因 | `ATT_COVER_PAGE_REASON_FOR_CHANGE` |

#### 输出字段（ET_ERROR 表）

同接口 2。

## 八、注意事项

1. **明文密码**：配置文件中 SAP 账号密码、MDM 密钥均为明文存储，存在安全风险。
2. **反编译代码**：本工程为 JD-Core 反编译产物，部分 import 缺失，不可直接编译。
3. **工厂增量同步**：接口1成功后会回写 Agile 物料的"已同步工厂"字段，避免重复创建。
4. **替代属性过滤**：BOM 接口中属性 `2000019515`（替代属性）用于控制哪些 BOM 行参与同步。
5. **雅迪 vs 凌博**：`ATT_PAGE_TWO_LIST01 = "Y"` 的物料走 MDM 接口时标记为"雅迪零部件"，否则为"凌博零部件"；同时该字段为 "Y" 的物料**不走** SAP 物料接口。

### 9.1 接口 1：物料主数据（ZFM_TR_MATERIAL）

#### 构建过程（伪代码）

```java
// 入口: ItemToSapTestPx.addItem(change, session)
// 或:   ItemToSapCreate.addItem() → 固定 addOrUpdate="01"
// 或:   ItemToSapUpdate.addItem() → 固定 addOrUpdate="02"

List<Map<String, Object>> itemAddOrUpdateList = new ArrayList<>();

// 1. 遍历变更单的"受影响物件"表
ITable table = change.getTable(ChangeConstants.TABLE_AFFECTEDITEMS);
for (IRow row : table) {
    IItem item = (IItem) row.getReferent();

    // 2. 过滤条件
    String isMdm = item.getCell(ATT_PAGE_TWO_LIST01).getValue();  // 是否MDM管理
    String apiName = item.getAgileClass().getSuperClass().getAPIName();
    if (!apiName.equals("PartsClass") || isMdm.equals("Y")) {
        continue;  // 跳过非零部件类 和 雅迪自管物料
    }

    // 3. 判断新增/修改
    String oldRev = row.getCell(ATT_AFFECTED_ITEMS_OLD_REV).getValue();
    String addOrUpdate;
    if (oldRev 为空) {
        addOrUpdate = "01";  // 创建
        // 清空"已同步工厂"字段，准备重新写入
        item.getCell(ATT_PAGE_TWO_MULTILIST02).setValue(空选择);
    } else {
        addOrUpdate = "02";  // 修改
    }

    // 4. 调用 addSapItem() 构建数据
    addSapItem(item, row, itemAddOrUpdateList, addOrUpdate);
}

// 5. 发送到 SAP
PlmRequestSap.plmToSapItem(itemAddOrUpdateList);
```

#### addSapItem() 构建逻辑

```java
void addSapItem(IItem item, IRow row, List<Map> list, String addOrUpdate) {

    // 获取工厂列表（Redline值，可能多个，分号分隔）
    String werks = AgileUtil.getRedlineValueByItem(item, 2090);  // 如 "1000;2000;3000"
    String[] werkList = werks.split(";");

    // ★ 关键：按工厂逐行构建，一个物料 × N个工厂 = N行数据
    for (String werk : werkList) {
        Map<String, Object> sapItem = new HashMap<>();

        // --- 操作类型 ---
        sapItem.put("ZCZLX", addOrUpdate);  // "01"创建 / "02"修改

        // --- 物料描述 ---
        String desc = AgileUtil.getValue(item, 1002);  // Description属性
        sapItem.put("ZCWB", desc);

        // --- 物料类型（取Redline列表的APIName） ---
        String itemType = AgileUtil.getRedlineListApi(item, 1274);
        sapItem.put("MTART", itemType);  // 如 "ZROH"(原材料), "ZHAL"(半成品)

        // --- 物料号逻辑（核心判断） ---
        String itemNumber = item.getName();           // 如 "X9841-0000428"
        String itemOldNumber = AgileUtil.getValue(item, 2011);  // 旧物料号

        if (addOrUpdate == "02") {  // 修改模式
            sapItem.put("MATNR", itemNumber);
            sapItem.put("BISMT", itemOldNumber);

            // 检查该工厂是否已同步过
            String syncedWerks = item.getCell(ATT_PAGE_TWO_MULTILIST02).getValue();
            if (!syncedWerks.contains(werk)) {
                // 该工厂未同步过 → 改为创建模式
                sapItem.put("MATNR", itemNumber);
                sapItem.put("BISMT", itemNumber);
                sapItem.put("ZCZLX", "01");  // 覆盖为创建
                if (itemOldNumber 非空) {
                    sapItem.put("BISMT_T", itemOldNumber);
                    sapItem.put("BISMT_X", "X");
                }
            } else {
                // 已同步过 → 正常修改
                sapItem.put("BISMT", itemNumber);
                sapItem.put("BISMT_T", itemOldNumber);
                sapItem.put("BISMT_X", "X");
            }
        } else {  // 创建模式 "01"
            if (werkList.length > 1) {
                // 多工厂：第一个工厂只传BISMT，后续工厂追加MATNR
                if (列表中不存在同BISMT的创建记录) {
                    sapItem.put("BISMT", itemNumber);
                } else {
                    sapItem.put("BISMT", itemNumber);
                    sapItem.put("MATNR", itemNumber);
                }
            } else {
                sapItem.put("BISMT", itemNumber);
            }
            if (itemOldNumber 非空) {
```

```java
void addUpdateBom(IItem item, IChange change, List<Map> list) {

    // 获取 Redline BOM 表（包含所有变更标记）
    ITable redlineBom = item.getTable(ItemConstants.TABLE_REDLINEBOM);

    // 获取上一版本的BOM（用于对比替代属性变化）
    List<IRow> lastRevBom = AgileUtils.getLastRevBomList(item, change);

    for (IRow bomRow : redlineBom) {
        IItem childItem = (IItem) bomRow.getReferent();
        Map<String, String> bom = new HashMap<>();

        // --- 公共字段 ---
        bom.put("PARENTNUM", item.getName());
        bom.put("SUBNUM", bomRow.getCell(ATT_BOM_ITEM_NUMBER).getValue());
        bom.put("SUBQUANTITY", bomRow.getCell(ATT_BOM_QTY).getValue());
        bom.put("SUBUNIT", bomRow.getCell(ATT_BOM_ITEM_LIST11).getValue());
        bom.put("LINENUM", bomRow.getCell(ATT_BOM_FIND_NUM).getValue());
        bom.put("FACTORYNUM", item.getCell(ATT_PAGE_TWO_LIST02).getValue());

        // 客供料
        String childType = childItem.getCell(1274).getValue();
        bom.put("ZKGL", childType == "客供物料类型" ? "X" : "");

        // --- 变更单信息 ---
        bom.put("MCNNUM", change.getCell(ATT_COVER_PAGE_NUMBER).getValue());  // 变更单号
        bom.put("EFFECTIVEDATE", LocalDate.now().format("yyyyMMdd"));         // 生效日期
        bom.put("AETXT", change.getCell(ATT_COVER_PAGE_REASON_FOR_CHANGE).getValue()); // 变更原因
        bom.put("SWITCHINGMODE", "01");  // 固定

        // --- ★ 操作类型判断（核心逻辑） ---
        String tdsx = bomRow.getCell(2000019515).getValue();  // 替代属性(新值)

        if (bomRow.isFlagSet(FLAG_IS_REDLINE_ADDED)) {
            // 新增行
            bom.put("OPERATIONTYPE", "01");
            if (tdsx 非空 && tdsx != "1") continue;  // 过滤非主替代
            list.add(bom);

        } else if (bomRow.isFlagSet(FLAG_IS_REDLINE_REMOVED)) {
            // 删除行
            if (tdsx 非空 && tdsx != "1") continue;
            bom.put("OPERATIONTYPE", "03");
            bom.put("SUBNUM", childItem.getName());  // 用实际物料号
            list.add(bom);

        } else if (bomRow.isFlagSet(FLAG_IS_REDLINE_MODIFIED)) {
            // 修改行 → 需要对比替代属性变化
            if (tdsx 非空) {
                // 在上一版本BOM中查找同一子件
                IRow oldRow = lastRevBom.find(ATT_BOM_ITEM_NUMBER == itemNumber);
                String oldTdsx = oldRow.getCell(2000019515).getValue();

                if (oldTdsx为空 || oldTdsx=="1") {
                    if (tdsx != "1") → OPERATIONTYPE = "03" (变删除)
                    else             → OPERATIONTYPE = "02" (修改)
                } else if (oldTdsx非空非1) {
                    if (tdsx == "1") → OPERATIONTYPE = "01" (变新增)
                    else             → continue (跳过)
                }
            } else {
                bom.put("OPERATIONTYPE", "02");  // 普通修改
            }
            list.add(bom);
        }
    }
}
```

### 9.5 数据提取方法说明

代码中从 Agile PLM 提取数据使用了三种方式：

| 方法 | 说明 | 使用场景 |
|------|------|---------|
| `AgileUtil.getValue(item, attrId)` | 直接读取物料当前属性值 | 描述(1002)、旧号(2011)、单位(1271) |
| `AgileUtil.getRedlineValueByItem(item, attrId)` | 读取 Redline（变更中）的属性值，遍历 TitleBlock/PageTwo/PageThree 三张 Redline 表 | 工厂(2090) |
| `AgileUtil.getRedlineListApi(item, attrId)` | 读取 Redline 列表属性，返回选中项的 **APIName**（非显示值） | 物料类型(1274)、产品层次(1275) |
| `row.getCell(attrId).getValue()` | 读取变更单受影响物件行的字段 | 生命周期阶段(1057) |
| `item.getAgileClass().getName()` | 获取物料所属 Agile Class 的显示名称 | 物料组（取前5位） |
| `item.getName()` | 物料编号 | SAP物料号/父物料号 |

#### Redline 值获取原理

```java
// getRedlineValueByItem 的核心逻辑：
// 依次读取物料的三张 Redline 表，将所有 cell 的 {id: value} 放入 map
// 最后用 attrId 从 map 中取值

Map<Object, Object> map = new HashMap<>();

// 1. Redline TitleBlock
ITable tbTable = item.getTable(TABLE_REDLINETITLEBLOCK);
for (ICell cell : tbTable.firstRow().getCells()) {
    map.put(cell.getId(), cell.getValue());
}

// 2. Redline PageTwo
ITable p2Table = item.getTable(TABLE_REDLINEPAGETWO);
for (ICell cell : p2Table.firstRow().getCells()) {
    map.put(cell.getId(), cell.getValue());
}

// 3. Redline PageThree
ITable p3Table = item.getTable(TABLE_REDLINEPAGETHREE);
for (ICell cell : p3Table.firstRow().getCells()) {
    map.put(cell.getId(), cell.getValue());
}

return map.get(attrId).toString();
```

### 9.6 SAP RFC 调用机制说明

SAP 接口不是 HTTP/JSON，而是通过 **SAP JCo（Java Connector）** 进行 RFC 调用：

```java
// 1. 获取连接（连接池模式）
JCoDestination connect = JCoDestinationManager.getDestination("ABAP_AS_WITH_POOL");

// 2. 获取函数模块
JCoFunction bapi = connect.getRepository().getFunction("ZFM_TR_MATERIAL");

// 3. 填充输入表参数
JCoParameterList inputlist = bapi.getTableParameterList();
JCoTable structure = inputlist.getTable("IT_DATA");

for (Map<String, Object> map : mapList) {
    structure.appendRow();                          // 新增一行
    for (Map.Entry<String, Object> entry : map.entrySet()) {
        structure.setValue(entry.getKey(), entry.getValue());  // 按字段名赋值
    }
}

// 4. 执行 RFC 调用
bapi.execute(connect);

// 5. 读取输出表
JCoTable resultTable = bapi.getTableParameterList().getTable("ET_DATA");
for (int i = 0; i < resultTable.getNumRows(); i++) {
    resultTable.setRow(i);
    String matnr = resultTable.getString("MATNR");
    String status = resultTable.getString("E_STATUS");   // S=成功, E=失败
    String msg = resultTable.getString("E_MSGTXT");
}
```

等效理解为：SAP RFC 的 `IT_DATA` 表就相当于 JSON 数组，每一行就是一个 Map 对象。

## 十一、HTTP POST 发送过程详解（接口 4 MDM）

### 11.1 完整调用链路

```
ItemToMdmTestPx.doAction()
  └→ ItemToMdmTestPx.addItem(change)
       ├→ 遍历受影响物件，构建 List<MdmItem>
       ├→ JSON.toJSONString(mdmItemList)     ← FastJSON 序列化
       └→ MdmUtil.sendPost(jsonBody)         ← HTTP 发送
            ├→ 创建 HttpClient
            ├→ 构建 HttpPost 对象
            ├→ 设置请求头
            ├→ 设置请求体
            ├→ 执行请求
            └→ 读取响应
```

### 11.2 逐步执行过程

#### 第 1 步：序列化 Java 对象为 JSON 字符串

```java
// ItemToMdmTestPx.addItem() 中
List<MdmItem> mdmItemList = new ArrayList<>();
// ... 填充 mdmItemList ...

// 使用 Alibaba FastJSON 将 List<MdmItem> 序列化为 JSON 数组字符串
String jsonBody = JSON.toJSONString(mdmItemList);
```

序列化规则：
- FastJSON 默认按字段名字母序输出
- null 值字段默认**不输出**（即如果 `number` 为 null，JSON 中不会出现该 key）
- 空字符串 `""` 会正常输出
- 输出结果示例：`[{"basic_units":"PC","factory":"1000;2000","industry_sector":"M",...}]`

#### 第 2 步：创建 HTTP 客户端

```java
// MdmUtil.sendPost() 中
CloseableHttpClient httpClient = HttpClients.createDefault();
```

- 使用 Apache HttpClient 4.x
- `createDefault()` 创建默认配置的客户端（无代理、无自定义超时、自动管理 Cookie）
- 使用 try-with-resources 确保连接关闭

#### 第 3 步：创建 POST 请求对象

```java
HttpPost httpPost = new HttpPost(MDM_URL);
```

- `MDM_URL` 从配置文件读取：
  - 生产：`https://mdm.yadea.com.cn/yadeaMdm/mdm/yadeaMat/matDataBulkOperation`
  - 测试：`http://10.149.5.104:28088/yadeaMdm/mdm/yadeaMat/matDataBulkOperation`

#### 第 4 步：设置请求头

```java
// 4.1 Accept 头 - 告知服务器期望接收 JSON 格式响应
httpPost.setHeader("Accept", "application/json");

// 4.2 客户端标识码 - MDM 平台用于识别调用方身份
httpPost.setHeader("x-mdm-client-code", "LBPLM_MAT_MDM");
// "LBPLM" = 凌博PLM，"MAT" = 物料，"MDM" = 主数据管理

// 4.3 客户端密钥 - 根据环境选择不同密钥
String env = ConfigUtil.getPropertyValue("env");  // 读取 config.properties 中的 env 值
if (env.equals("pro")) {
    httpPost.setHeader("x-mdm-client-secret", "5376c4B17891F947c85BA4658Cc8f904b899");
} else {
    httpPost.setHeader("x-mdm-client-secret", "42A241E829Cf2643e018D65120c3513DED2B");
}

// 4.4 Content-Type - 声明请求体格式
httpPost.setHeader("Content-Type", "application/json;charset=UTF-8");
```

最终请求头完整列表：
```
Accept: application/json
x-mdm-client-code: LBPLM_MAT_MDM
x-mdm-client-secret: 5376c4B17891F947c85BA4658Cc8f904b899
Content-Type: application/json;charset=UTF-8
```

> ⚠️ **注意**：MDM 请求只携带上述 4 个头和 JSON 请求体，**不包含** SAP 连接凭据（`SAP.CLIENT`/`SAP.USER`/`SAP.LANG`/`SAP.SYSNR` 等）。MDM 平台的身份认证完全依赖 `x-mdm-client-code` + `x-mdm-client-secret`；生产环境（`env=pro`）自动使用 pro 密钥（MdmUtil.java:56-64）。

#### 第 5 步：设置请求体

```java
// 将 JSON 字符串包装为 StringEntity，指定 UTF-8 编码
StringEntity requestEntity = new StringEntity(requestBody, StandardCharsets.UTF_8);

// 将 entity 绑定到 POST 请求
httpPost.setEntity(requestEntity);
```

- `StringEntity` 是 Apache HttpClient 的字符串实体类
- 指定 `StandardCharsets.UTF_8` 确保中文正确编码
- 请求体就是第 1 步生成的 JSON 字符串原文

#### 第 6 步：执行 HTTP 请求

```java
CloseableHttpResponse response = httpClient.execute(httpPost);
```

底层执行过程：
1. DNS 解析 `mdm.yadea.com.cn`
2. 建立 TCP 连接（生产环境为 HTTPS，需 TLS 握手）
3. 发送 HTTP 请求报文：
   ```
   POST /yadeaMdm/mdm/yadeaMat/matDataBulkOperation HTTP/1.1
   ```

| 项目 | 说明 |

#### 第 2 步：获取连接实例


#### 第 6 步：执行 RFC 远程调用

```java

```

底层执行过程：
1. JCo 将函数模块名 `ZFM_TR_MATERIAL` 和所有输入参数序列化为 SAP RFC 协议报文
2. 通过已建立的 TCP 连接发送到 SAP 应用服务器
3. SAP 服务器接收请求，在 ABAP 运行时中执行函数模块 `ZFM_TR_MATERIAL`
4. 函数模块内部逻辑（ABAP 代码）：
   - 遍历 IT_DATA 表每一行
   - 根据 ZCZLX 判断调用 BAPI_MATERIAL_SAVEDATA（创建）或修改逻辑
   - 将处理结果写入 ET_DATA 表
5. SAP 将输出参数（ET_DATA 表）序列化后返回给 JCo 客户端
6. JCo 反序列化填充到 `bapi` 对象的输出参数中

**这是同步阻塞调用**：Java 线程等待 SAP 处理完毕后才继续。

### 12.3 SAP RFC 与 HTTP REST 的对比

| 对比项 | SAP RFC (JCo) | HTTP REST (MDM) |
|--------|--------------|-----------------|
| 协议 | SAP 私有 RFC 协议（基于 TCP） | HTTP/HTTPS |
| 数据格式 | SAP 内部表结构（类似关系表） | JSON |
| 连接方式 | 长连接 + 连接池 | 短连接（每次新建） |
| 认证 | SAP 用户/密码（client+user+passwd） | Header 中的 client-code + client-secret |
| 服务发现 | Message Server 负载均衡 | DNS 解析 |
| 调用方式 | `bapi.execute()` 同步阻塞 | `httpClient.execute()` 同步阻塞 |
| 错误处理 | 返回表中的 E_STATUS 字段 | HTTP 状态码 + JSON 中的 code 字段 |
| 事务性 | SAP 内部可回滚（LUW） | 无事务保证 |
